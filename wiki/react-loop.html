排程 Wiki / 概念整理

排程循環：產生 → 檢查 → 修正

把檢查輸出當成下一輪輸入，避免整張日程盲目重排。

四步循環

先產生事件草稿，再呼叫規則工具；讀取事件 ID 與違規原因，修正受影響任務後重跑。這是受 ReAct 啟發的教學流程，沒有重現其模型實驗。

一次局部修正

衝突草稿 T1 為 15:30–17:00，與固定工作 F1 15:00–16:00 重疊。只把 T1 改成 16:00–17:30，固定事件、T2、T3 保持不動。

修正仍要驗收

只消除重疊不夠。把 T1 縮成 60 分鐘會違反所需 90 分鐘；移到 19:30–21:00 則超過 18:00 截止。每輪仍須完整核對全部硬條件。

何時退出

資料不足先詢問；通過則交人確認；失敗可局部修正，滿三輪仍失敗就停止。三輪是本作業的停止規則，並非 ReAct 論文結論。
