ReAct、Toolformer、Reflexion 一樣嗎？

三篇研究處理不同層次，不能只因都有工具就視為同一方法。

先分層，才比較

ReAct、Toolformer、Reflexion 討論代理機制；AgentBench、WebArena 提供互動任務評量環境。它們不在同一比較層次，不能直接排出單一高低名次。

三個機制差異

ReAct：在主要提示設定交錯推理、動作與觀察，論文也含微調實驗。Toolformer：產生、執行、篩選 API 資料再微調。Reflexion：以文字回饋與情節記憶影響後續嘗試，不更新權重。

為何不直接比較百分比

資料集、模型、工具權限、可嘗試次數及指標不同。WebArena 的任務成功率、程式生成 pass@1 或問答分數不是同一把尺。應先固定條件，才討論差異。

跨文獻結論

綜合推論：動作需要可讀的觀察、反思需要可信評估、驗收需要可觀察的完成條件。沒有哪一篇單獨證明排程助手一定可靠；本作業用局部可重跑檢查把觀點落實。

五篇研究的層次、機制與限制

此表是本 Wiki 的綜合整理；每列均連回原始證據，沒有以不同任務的百分比做單一排名。

研究／層次機制與改變限制排程情境中的借鑑
ReAct互動機制在主要提示設定中交錯推理、動作、觀察；另有微調分析當前上下文／後續決策；依所選設定可能另訓練可能重複與檢索失敗；不是有 loop 就成功讀取排程檢查結果後再決定修正位置C01, C02, C10, C16
Toolformer工具學習生成、執行、篩選 API 訓練資料，再微調模型權重；推論時加入工具結果該評估每輸入至多一次 API；不等於多步驟日曆代理明確區分工具名稱、時間參數與回傳狀態C03, C04, C11
Reflexion回饋與記憶Actor、Evaluator、Self-Reflection 角色分工文字反思與情節記憶；此機制不更新權重依賴回饋品質，沒有形式成功保證記錄衝突原因與可執行修正，再次檢查C05, C12, C13
AgentBench評量框架跨互動環境觀察多輪決策與結束原因評量狀態與失敗分類；不是生成演算法正常結束仍需驗收；不同環境指標不可亂排名分清缺資料、無效草稿、達上限與驗收通過C06, C07, C14
WebArena網站評量環境可部署網站、任務與功能結果檢查網站狀態／答案依任務驗收特定可重現環境與歷史模型，不代表任意真實網站檢查事件與期限，不以流暢文字當完成證明C08, C09, C15

AgentBench 區分格式無效、動作無效、上下文或任務輪數超限等結束原因；正常結束與任務成功仍須分開判斷。
