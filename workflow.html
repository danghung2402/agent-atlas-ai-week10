THE WORKFLOW GRAPH

大流程預先設計，
小範圍反覆修正。

本次由 AI 依檔案節點推進，腳本執行固定檢查；沒有宣稱是全自動模型編排系統。

NODE 01

取得資料

輸入：固定版本 PDF

raw/S01–S05.pdf

檢查：版本／格式／SHA-256

資料不全 → 留在本關
NODE 02

證據卡

輸入：單篇 PDF

content/claims.json

檢查：頁碼、章節、定位詞

主張錯誤 → 重讀該篇
NODE 03

整理 Wiki

輸入：已核對證據卡

wiki/*.md

檢查：關聯、反向連結、限制

缺概念 → 修該頁
NODE 04

查詢與覆蓋關卡

輸入：Wiki＋三個教學問題

content/queries.json

檢查：五篇來源全部納入

未滿五篇 → 回查詢
NODE 05

大綱與逐頁稿

輸入：已選頁面＋證據卡

content/deck.json

檢查：14 頁、每頁證據、數字

引用不全 → 只修該頁
NODE 06

語意核對

輸入：逐頁稿＋引用原文

content/review.json

檢查：忠實度、條件、教學標籤

概念錯 → 回證據／逐頁稿
NODE 07

渲染 HTML

輸入：已核對逐頁稿

dist/deck.html

檢查：不改字、可讀、可操作

版面錯 → 只修 CSS／HTML
NODE 08

驗收與發布

輸入：成品＋檢查報告

evidence/、公開網站

檢查：結構＋瀏覽器＋人工驗收

超過三輪 → 停止回報

觸發：主題、來源或逐頁稿變更時重跑。限制：生成內容只用 Wiki 已納入的證據；不補造數字。完成：來源、引用、覆蓋、連結、渲染與互動檢查通過。停止：資料不足、原文無法核驗，或修正滿三輪仍失敗。人工決策：主題偏好、公開權限與最後繳交；本次公開權限已由使用者授權。

為什麼這樣設計？

來源錯誤會影響後面所有頁面，所以提早抽出證據卡。引用缺失與版面問題則留在局部小圈修，避免每次整份重寫。三輪上限防止無止境重試；無法判斷時留下問題，交給人決定。
